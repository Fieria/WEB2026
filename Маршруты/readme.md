# Маршруты
## Структура 

- `index.js` — вся логика приложения (маршруты, CORS, вычисление даты)
- `package.json` — конфигурация проекта с `"type": "module"`


## Реализованные маршруты

| Маршрут | Описание |
|---|---|
| `/DDMMYY/` (например `/021023/`) | Возвращает логин, если параметр совпадает с сегодняшней датой в формате `ДДММГГ` |
| `/add/:x1/:x2/` | Возвращает сумму `x1` и `x2` в виде текста |
| `/mpy/:y1/:y2/` | Возвращает произведение `y1` и `y2` в виде текста |

## Настройка CORS

Middleware добавляет ко всем ответам заголовки:

Access-Control-Allow-Origin: *

Access-Control-Allow-Methods: GET,POST,PUT,DELETE,OPTIONS

Access-Control-Allow-Headers: x-test,ngrok-skip-browser-warning,Content-Type,Accept,Access-Control-Allow-Headers


Preflight-запросы (`OPTIONS`) обрабатываются отдельно — сервер отвечает `204 No Content`, не доходя до логики маршрутов. Все маршруты реагируют одинаково на любой HTTP-метод через `app.all(...)`.

## Особенность вычисления даты

Текущая дата вычисляется с учётом московского часового пояса (UTC+3), так как задание ориентировано на российских проверяющих. Проверка построена так: сначала подтверждается, что параметр состоит ровно из 6 цифр, затем — что он совпадает с сегодняшней датой; при несовпадении запрос передаётся дальше через `next()`.
